## 배경

이미지만 있으면 AI가 숏폼을 만들어주고, 그 결과물을 바로 콘텐츠 라이브러리에 등록할 수 있게 하는 기능이다. 크레딧을 차감하는 유료 기능이라 "그냥 만들어지면 되는" 수준으로 끝나지 않았다.

## 문제 정의

생성은 오래 걸리고, 그 사이에 유저는 탭을 닫거나 새로고침하거나 뒤로 간다. 여기에 크레딧 차감이 얽히면 문제가 복잡해진다. 돈이 빠져나갔는데 결과물이 없거나, 반대로 한 번의 요청으로 두 번 차감되는 상황은 모두 유저에게 직접적인 피해가 된다.

## 실패 조건

- 크레딧은 차감됐는데 생성물이 없는 경우
- 한 번의 요청이 중복 생성 또는 중복 차감으로 이어지는 경우
- 결제 후 돌아왔을 때 생성이 이어지지 않고 처음부터 다시 해야 하는 경우

## 접근

생성 플로우 자체를 상태 모델로 먼저 정의했다. 어떤 상태에서 어떤 전이가 가능한지를 정해두고, 크레딧 조회·차감·부족 처리와 결제 후 생성 재개를 그 상태 위에 얹었다.

## 구현

- 폴링 기반으로 생성 상태를 동기화하고, 단계별 재시도를 붙였다
- 이탈 가드를 두어 생성 도중 이탈하는 경우를 처리했다
- 중복 생성 / 중복 차감 / 중복 등록을 각각 막는 장치를 넣었다
- FE와 BE를 함께 맡아 API 계약과 상태 전이를 같은 기준으로 설계했다

## 결과

현재 운영 중인 유료 기능으로, 크레딧 결제와 비동기 생성이 하나의 플로우 안에서 끊기지 않고 이어진다.

## 배운 점

"돈이 걸린 비동기 작업"은 성공 경로보다 실패 경로가 훨씬 많다. 실패 조건을 먼저 나열하고 시작했더니, 나중에 급하게 막는 예외 처리가 확실히 줄었다.
